## Overview

### What Gets Published

1. **Swift source code** - Generated by UniFFI from Rust (in `bindings/swift/Sources/Bark/`)
2. **XCFramework binary** - Compiled Rust library for iOS and macOS (hosted on GitLab releases)
3. **Package.swift** - SPM manifest at repository root (references the XCFramework URL)

### Why Package.swift Must Be at Root

Swift Package Manager requires `Package.swift` at the repository root to resolve packages by URL:

```swift
// This works because Package.swift is at root:
.package(url: "https://gitlab.com/ark-bitcoin/bark-ffi.git", from: "0.1.0")

// If Package.swift were in bindings/swift/, users couldn't fetch remotely
```

### Repository Structure

```
bark-ffi/
├── Package.swift              ← Swift package manifest (MUST be at root!)
├── Cargo.toml                 ← Rust package manifest
├── .gitlab-ci.yml             ← CI/CD configuration
├── uniffi.toml                ← UniFFI configuration
├── src/                       ← Rust FFI implementation
│   ├── bark.udl               ← UniFFI interface definition
│   └── *.rs                   ← Rust sources
└── bindings/
    ├── swift/                 ← Swift bindings
    │   ├── build-swift.sh     ← Build script
    │   ├── Sources/Bark/      ← Generated Swift code (after build)
    │   ├── resources/         ← Static framework resources
    │   └── README.md          ← User documentation
    └── dart/                  ← Dart bindings
```

## First-Time Setup

### Step 1: Build Locally

Test that everything works before publishing:

```bash
cd bindings/swift
./build-swift.sh
```

This will:

1. Build Rust library for iOS (arm64 device + x86_64/arm64 simulator) and macOS (arm64 + x86_64)
2. Generate Swift bindings using UniFFI
3. Create XCFramework combining all platforms
4. Copy Swift sources to `Sources/Bark/`
5. Create `BarkFFI.xcframework.zip` for distribution
6. Output a checksum for Package.swift

**Expected output:**

```
✅ Build complete!

📦 XCFramework: /path/to/build/xcframework/BarkFFI.xcframework.zip
📝 Swift sources: /path/to/Sources/Bark

📊 Checksum for Package.swift:
   abc123def456789...
```

### Step 2: Manual First Release

Since CI/CD needs a working Package.swift to reference, create the first release manually:

#### 2a. Create GitLab Release

1. Go to GitLab: Repository → Releases → New Release
2. Tag: `v0.1.0`
3. Title: `v0.1.0 - Initial Swift Bindings`
4. Upload `BarkFFI.xcframework.zip` from `build/xcframework/`
5. Publish release

#### 2b. Get Release URL

After creating the release, the XCFramework will be available at:

```
https://gitlab.com/ark-bitcoin/bark-ffi/-/releases/v0.1.0/downloads/BarkFFI.xcframework.zip
```

Verify it's downloadable:

```bash
curl -I https://gitlab.com/ark-bitcoin/bark-ffi/-/releases/v0.1.0/downloads/BarkFFI.xcframework.zip
# Should return: HTTP/2 200
```

### Step 3: Update Package.swift

Edit [Package.swift](../../Package.swift) at the repository root:

```swift
.binaryTarget(
    name: "BarkFFI",
    url: "https://gitlab.com/ark-bitcoin/bark-ffi/-/releases/v0.1.0/downloads/BarkFFI.xcframework.zip",
    checksum: "abc123def456789..."  // Use checksum from Step 1
)
```

**Important:** Both the URL and checksum must be correct, or users won't be able to install the package.

### Step 4: Commit and Push

```bash
cd ../..  # back to repo root
git add Package.swift bindings/swift/
git commit -m "Add Swift bindings v0.1.0 with XCFramework support"
git push origin main  # or your branch name
```

**Note:** The tag (v0.1.0) was already created in Step 2a.

### Step 5: Verify Installation

Test that users can install the package:

```bash
# Create test project
mkdir /tmp/test-bark && cd /tmp/test-bark
swift package init --type executable

# Add Bark as dependency
cat > Package.swift << 'EOF'
// swift-tools-version: 5.9
import PackageDescription

let package = Package(
    name: "test-bark",
    platforms: [.iOS(.v13), .macOS(.v12)],
    dependencies: [
        .package(url: "https://gitlab.com/ark-bitcoin/bark-ffi.git", from: "0.1.0")
    ],
    targets: [
        .executableTarget(
            name: "test-bark",
            dependencies: ["Bark"])
    ]
)
EOF

# Resolve and build
swift package resolve
swift build
```

If this succeeds, your package is published correctly! 🎉

## Swift Package Index Registration

[Swift Package Index](https://swiftpackageindex.com/) helps developers discover your package by providing:

- Searchable listing with documentation
- Platform and Swift version compatibility
- Build status monitoring
- Usage statistics

### Prerequisites for Registration

- [x] Repository is public on GitLab
- [x] `Package.swift` at repository root
- [x] At least one tagged release (v0.1.0)
- [x] LICENSE file present
- [x] README.md with usage examples

### Registration Options

#### Option A: Manual Submission (Recommended)

1. Go to: https://github.com/SwiftPackageIndex/PackageList/issues
2. Click **New Issue**
3. Fill out the template:

```
Title: Add Bark - Ark Wallet for Bitcoin (Swift Bindings)

Repository URL: https://gitlab.com/ark-bitcoin/bark-ffi

Description:
Swift bindings for Bark, an Ark protocol Bitcoin wallet.
Provides native iOS and macOS support for instant, low-fee Bitcoin transactions.

Categories: Blockchain, Cryptocurrency, Bitcoin, Payments
```

4. Wait for maintainers to review (typically 24-48 hours)

#### Option B: Fork and Submit PR (Fastest)

1. Fork: https://github.com/SwiftPackageIndex/PackageList
2. Edit `packages.json` and add:
   ```json
   {
     "url": "https://gitlab.com/ark-bitcoin/bark-ffi"
   }
   ```
3. Submit PR with title: "Add Bark - Ark Wallet for Bitcoin"
4. Wait for approval

### After Registration

Once approved, your package will appear at:

```
https://swiftpackageindex.com/ark-bitcoin/bark-ffi
```

Swift Package Index will:

- Build your package for all platforms
- Extract documentation from README
- Monitor for new releases
- Display compatibility information

### Improve Discoverability

Add topics to your GitLab repository:

- **GitLab**: Settings → General → Topics
- **Suggested**: `swift`, `bitcoin`, `ark`, `wallet`, `lightning`, `ios`, `macos`, `spm`

## Subsequent Releases

After the first release, use CI/CD for automation:

### Step 1: Make Changes

Update Rust code in `src/` or `.udl` files as needed.

### Step 2: Tag Release

```bash
git tag v0.2.0
git push origin v0.2.0
```

### Step 3: CI/CD Builds Automatically

The `.gitlab-ci.yml` pipeline will:

1. Build XCFramework for all platforms
2. Upload to GitLab Package Registry
3. Create release with attached artifact
4. Output new checksum

### Step 4: Update Package.swift

After CI/CD completes:

1. Check the pipeline output for the new checksum
2. Update [Package.swift](../../Package.swift):
   ```swift
   url: "https://gitlab.com/ark-bitcoin/bark-ffi/-/releases/v0.2.0/downloads/BarkFFI.xcframework.zip",
   checksum: "new_checksum_here"
   ```
3. Commit and push:
   ```bash
   git add Package.swift
   git commit -m "Update Package.swift for v0.2.0"
   git push origin main
   ```

### Step 5: Verify

Swift Package Index will automatically detect the new release and rebuild.

## Troubleshooting

### Build Fails Locally

**Problem**: `./build-swift.sh` fails with Rust errors

**Solution**:

- Ensure Rust toolchain is up to date: `rustup update`
- Check all required targets are installed:
  ```bash
  rustup target add aarch64-apple-ios x86_64-apple-ios aarch64-apple-ios-sim
  rustup target add aarch64-apple-darwin x86_64-apple-darwin
  ```
- Verify Cargo.toml dependencies are valid

**Problem**: UniFFI generation fails

**Solution**:

- Check uniffi version matches in Cargo.toml (0.30.0)
- Verify `.udl` file syntax is valid
- Run `cargo build` first to ensure Rust code compiles

### CI/CD Issues

**Problem**: No macOS runner available

**Solution**:

- Set up self-hosted GitLab runner on macOS, OR
- Use external CI (GitHub Actions, CircleCI), OR
- Build manually and upload artifacts

**Problem**: CI/CD builds but doesn't create release

**Solution**:

- Ensure you pushed a tag: `git push origin v0.x.x`
- Check `.gitlab-ci.yml` has `only: - tags` configured
- Verify GitLab permissions allow creating releases

### Package Installation Fails

**Problem**: `swift package resolve` fails with "binary artifact failed to download"

**Solution**:

- Verify XCFramework URL is correct and public
- Test URL: `curl -I <xcframework-url>` should return 200
- Ensure release was created on GitLab
- Check there are no typos in Package.swift

**Problem**: Checksum mismatch error

**Solution**:

- Regenerate checksum: `swift package compute-checksum BarkFFI.xcframework.zip`
- Update Package.swift with exact checksum from build output
- Ensure you're using the correct XCFramework (not from a different build)

**Problem**: Users can't fetch package by URL

**Solution**:

- Verify Package.swift is at repository root (not in `bindings/swift/`)
- Check repository is public on GitLab
- Ensure tag exists: `git tag -l`

### Swift Package Index Issues

**Problem**: Package not indexed after submission

**Solution**:

- Wait 24-48 hours for initial indexing
- Verify repository is public
- Check Package.swift is valid: `swift package describe`
- Ensure at least one release tag exists

**Problem**: Build fails on Swift Package Index

**Solution**:

- Check build logs on swiftpackageindex.com
- Common issues:
  - Binary target URL returns 404
  - Checksum doesn't match
  - Package.swift has syntax errors
- Fix issues and push a new release
