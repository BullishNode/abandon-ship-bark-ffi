## Overview

### What Gets Published

We publish **two separate modules**:

1. **bark-android** - Android library (AAR)

   - Kotlin source code generated by UniFFI
   - Native `.so` libraries for 4 Android architectures
   - Packaged as AAR for Android apps

2. **bark-jvm** - JVM library (JAR)
   - Same Kotlin source code (UniFFI-generated)
   - Native library for host platform (`.so` or `.dylib`)
   - Packaged as JAR for desktop/server apps

### Version Strategy

- **Library version**: `0.1.0-beta.4` (matches the base version of the bark library)
- **Git tag format**: `kotlin-v0.1.0-beta.4` (prefixed to distinguish from other bindings)
- Internal bark dependency is pinned to commit `7f625dffd598c23127f69590294ae7c397458d23`

## Publishing to JitPack (Recommended)

[JitPack.io](https://jitpack.io) is the recommended publishing method for GitLab-hosted projects. It builds both modules directly from Git tags with zero configuration required.

### Why JitPack?

✅ **Works seamlessly with GitLab** (no GitHub requirement)
✅ **Automatic builds** from Git tags for both modules
✅ **No manual artifact uploads**
✅ **No GPG signing required**
✅ **Free for public repositories**
✅ **No account setup needed**

### How JitPack Works

1. You tag a release in Git (e.g., `kotlin-v0.1.0-beta.4`)
2. When a user requests either dependency, JitPack:
   - Clones the repository
   - Checks out the tag
   - Runs the build according to `jitpack.yml`
   - Builds both `bark-android` and `bark-jvm`
   - Caches the built artifacts (AAR + JAR)
   - Serves them to users

### First-Time Publishing

#### Step 1: Build Locally (Test First)

Before publishing, verify both modules build successfully:

```bash
cd bindings/kotlin
./build-kotlin.sh
```

Expected output:

```
✅ Build complete!
===============

📦 Artifacts:
   Android AAR: bark-android/build/outputs/aar/bark-android-release.aar
   JVM JAR:     bark-jvm/build/libs/bark-jvm-*.jar

📝 Kotlin sources:
   Android: bark-android/src/main/kotlin/uniffi/bark/
   JVM:     bark-jvm/src/main/kotlin/uniffi/bark/
```

#### Step 2: Test Both Modules

**Android:**

```bash
cd example
./gradlew installDebug
# Run on emulator/device to verify
```

**JVM:**

```bash
cd example-jvm
../gradlew run
# Verify output shows wallet creation and address generation
```

#### Step 3: Run Tests

```bash
# JVM tests (fast)
./gradlew :bark-jvm:test

# Android tests (requires emulator)
./gradlew :bark-android:connectedAndroidTest
```

#### Step 4: Check Code Quality

```bash
# Check Kotlin code style
./gradlew ktlintCheck

# Generate API documentation
./gradlew dokkaHtml
```

#### Step 5: Commit and Tag

```bash
cd ../../..  # back to repo root
git add bindings/kotlin/
git commit -m "Add Kotlin bindings v0.1.0-beta.4 (Android + JVM)"
git tag kotlin-v0.1.0-beta.4
git push origin master
git push origin kotlin-v0.1.0-beta.4
```

#### Step 6: Trigger JitPack Build

Visit JitPack and trigger a test build:

```
https://jitpack.io/#ark-bitcoin/bark-ffi/kotlin-v0.1.0-beta.4
```

Click **"Get it"** to trigger the build. You can watch the build log in real-time.

JitPack will build both modules:

- `com.gitlab.ark-bitcoin.bark-ffi:bark-android:kotlin-0.1.0-beta.4`
- `com.gitlab.ark-bitcoin.bark-ffi:bark-jvm:kotlin-0.1.0-beta.4`

#### Step 7: Verify Installation

Test that users can install both packages:

**For Android:**

```kotlin
// In a test Android project's settings.gradle.kts
dependencyResolutionManagement {
    repositories {
        google()
        mavenCentral()
        maven { url = uri("https://jitpack.io") }
    }
}

// In app/build.gradle.kts
dependencies {
    implementation("com.gitlab.ark-bitcoin.bark-ffi:bark-android:kotlin-0.1.0-beta.4")
}
```

**For JVM:**

```kotlin
// In build.gradle.kts
repositories {
    mavenCentral()
    maven { url = uri("https://jitpack.io") }
}

dependencies {
    implementation("com.gitlab.ark-bitcoin.bark-ffi:bark-jvm:kotlin-0.1.0-beta.4")
}
```

Run `./gradlew build` and verify both resolve and build successfully.

### Subsequent Releases

For future releases:

1. Make changes to Rust code or UDL
2. Run `./build-kotlin.sh` to regenerate bindings
3. Test both modules locally
4. Run tests: `./gradlew test`
5. Update version in `gradle.properties` (if changing)
6. Commit, tag, and push:
   ```bash
   git tag kotlin-v0.2.0-beta.1
   git push origin kotlin-v0.2.0-beta.1
   ```
7. JitPack will automatically build both modules on first user request

### JitPack Configuration

The `jitpack.yml` file tells JitPack how to build both modules:

```yaml
jdk:
  - openjdk17

before_install:
  # Install Rust toolchain
  - curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- -y
  - source $HOME/.cargo/env
  # Add Android and JVM targets
  - rustup target add aarch64-linux-android armv7-linux-androideabi x86_64-linux-android i686-linux-android
  - rustup target add x86_64-unknown-linux-gnu
  # Navigate to Kotlin bindings directory
  - cd bindings/kotlin

install:
  # Run the build script to compile Rust for both Android and JVM
  - ./build-kotlin.sh
  # Build both modules
  - ./gradlew :bark-android:assembleRelease :bark-jvm:jar
```

## Alternative: Maven Central

Publishing to Maven Central is more complex but provides broader discoverability.

### Prerequisites

1. **Sonatype OSSRH Account** - Sign up at [issues.sonatype.org](https://issues.sonatype.org)
2. **GPG Key** - For signing artifacts
3. **Group ID** - Claim `tech.second` or use `io.github.yourusername`

### Configuration

Both `bark-android/build.gradle.kts` and `bark-jvm/build.gradle.kts` already include publishing configuration. Uncomment the signing section:

```kotlin
signing {
    val signingKey = findProperty("SIGNING_KEY") as String?
    val signingPassword = findProperty("SIGNING_PASSWORD") as String?
    if (signingKey != null && signingPassword != null) {
        useInMemoryPgpKeys(signingKey, signingPassword)
        sign(publishing.publications["release"]) // or ["maven"] for JVM
    }
}
```

### Publishing Steps

```bash
# Build both modules
./build-kotlin.sh

# Publish Android to staging
./gradlew :bark-android:publishReleasePublicationToOSSRHRepository

# Publish JVM to staging
./gradlew :bark-jvm:publishMavenPublicationToOSSRHRepository

# Release from staging repository via Sonatype Nexus UI
```

**Note**: Maven Central publishing is significantly more complex. We recommend JitPack for most use cases.

## Building Locally

To build both modules for manual distribution or testing:

```bash
cd bindings/kotlin
./build-kotlin.sh
```

Artifacts:

- Android AAR: `bark-android/build/outputs/aar/bark-android-release.aar`
- JVM JAR: `bark-jvm/build/libs/bark-jvm-0.1.0-beta.4.jar`

### Using Local Artifacts

**Android (local AAR):**

```kotlin
// settings.gradle.kts
dependencyResolutionManagement {
    repositories {
        google()
        mavenCentral()
        flatDir {
            dirs("libs")
        }
    }
}

// app/build.gradle.kts
dependencies {
    implementation(name: "bark-android-release", ext: "aar")
    implementation("net.java.dev.jna:jna:5.14.0@aar")
}
```

Place `bark-android-release.aar` in `app/libs/`.

**JVM (local JAR):**

```kotlin
dependencies {
    implementation(files("libs/bark-jvm-0.1.0-beta.4.jar"))
    implementation("net.java.dev.jna:jna:5.14.0")
}
```

## CI/CD Integration

### GitLab CI

Add to `.gitlab-ci.yml`:

```yaml
build-kotlin-bindings:
  stage: build
  image: circleci/android:api-34
  before_script:
    # Install Rust
    - curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- -y
    - source $HOME/.cargo/env
    # Add Android and JVM targets
    - rustup target add aarch64-linux-android armv7-linux-androideabi
    - rustup target add x86_64-linux-android i686-linux-android
    - rustup target add x86_64-unknown-linux-gnu
  script:
    - cd bindings/kotlin
    - ./build-kotlin.sh
    - ./gradlew :bark-jvm:test
  artifacts:
    paths:
      - bindings/kotlin/bark-android/build/outputs/aar/bark-android-release.aar
      - bindings/kotlin/bark-jvm/build/libs/bark-jvm-*.jar
    expire_in: 1 week
  only:
    - tags
    - master
```

### Automated JitPack Publishing

No CI/CD needed! Just tag and push. JitPack handles the rest.

## Troubleshooting

### Build Fails: "cargo not found"

**Solution**: Install Rust toolchain:

```bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
source $HOME/.cargo/env
```

### Build Fails: "Android NDK not found"

**Solution**: Set NDK path:

```bash
export ANDROID_NDK_HOME=$HOME/Android/Sdk/ndk/26.1.10909125
```

Or install via Android Studio: SDK Manager → SDK Tools → NDK

### Build Fails: "Rust target not installed"

**Solution**: Install missing targets:

```bash
# Android
rustup target add aarch64-linux-android armv7-linux-androideabi
rustup target add x86_64-linux-android i686-linux-android

# JVM (Linux)
rustup target add x86_64-unknown-linux-gnu

# JVM (macOS)
rustup target add aarch64-apple-darwin x86_64-apple-darwin
```

### JitPack Build Fails

**Problem**: JitPack build log shows errors

**Solution**:

1. Check the build log at `https://jitpack.io/com/gitlab/ark-bitcoin/bark-ffi/kotlin-v0.1.0-beta.4/build.log`
2. Common issues:
   - Rust compilation errors: Fix Rust code and re-tag
   - Gradle errors: Test `./gradlew :bark-android:assembleRelease :bark-jvm:jar` locally
   - NDK issues: Ensure `jitpack.yml` installs Android targets
3. Re-tag after fixing:
   ```bash
   git tag -d kotlin-v0.1.0-beta.4
   git push origin :refs/tags/kotlin-v0.1.0-beta.4
   git tag kotlin-v0.1.0-beta.4
   git push origin kotlin-v0.1.0-beta.4
   ```

### Library Not Found at Runtime (Android)

**Problem**: `java.lang.UnsatisfiedLinkError: libbark_ffi.so not found`

**Solution**:

- Verify .so files are in `bark-android/src/main/jniLibs/{arch}/`
- Check AAR contains jniLibs: `unzip -l bark-android-release.aar | grep jniLibs`
- Ensure JNA dependency is included: `implementation("net.java.dev.jna:jna:5.14.0@aar")`

### Library Not Found at Runtime (JVM)

**Problem**: Native library not loaded

**Solution**:

- Verify native lib is in `bark-jvm/src/main/resources/`
- Check JAR contains library: `jar tf bark-jvm-*.jar | grep libbark_ffi`
- Ensure JNA dependency is included: `implementation("net.java.dev.jna:jna:5.14.0")`

### Tests Fail

**Problem**: Android instrumented tests fail

**Solution**:

- Ensure emulator is running: `adb devices`
- Use x86_64 or arm64-v8a emulator (matches built architectures)
- Check logcat for errors: `adb logcat | grep Bark`

**Problem**: JVM unit tests fail

**Solution**:

- Ensure JVM 17+ is installed: `java -version`
- Check native library was built for your platform
- Run with `--stacktrace`: `./gradlew :bark-jvm:test --stacktrace`

### Gradle Sync Fails: "Could not resolve dependency"

**Problem**: Android Studio can't resolve JitPack dependency

**Solution**:

1. Add JitPack repo to `settings.gradle.kts`:
   ```kotlin
   maven { url = uri("https://jitpack.io") }
   ```
2. Ensure correct dependency format:
   ```kotlin
   implementation("com.gitlab.ark-bitcoin.bark-ffi:bark-android:kotlin-0.1.0-beta.4")
   ```
3. Sync project with Gradle files
4. Check JitPack built successfully at jitpack.io
